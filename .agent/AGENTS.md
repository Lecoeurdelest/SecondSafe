# SecondSafe agent contract

Shared instructions for every coding agent and human contributor. Tool-specific files (`AGENTS.md`, `CLAUDE.md` at the root) only point here.

## Read first

1. `plan.md`: intent, invariants, decisions
2. `docs/task/README.md`: task status and dependencies
3. The task specification `docs/task/TASK-NNN.md`, or a bundle from `python3 tools/pdd/render.py bundle TASK-NNN`
4. `docs/technical/architecture.md`, `docs/technical/data-model.md`, and `docs/technical/order-lifecycle.md` for order or money work
5. `.agent/rules/*.md`

## One authority per fact

| Fact | Authority | Writable by hand |
|---|---|---|
| Goals, scope, invariants, decisions | `plan.md` (outside the generated progress region) | yes |
| Requirements, criteria, tasks, decision status | `project.yaml` | yes, consistent with plan.md |
| Task execution state and history | `.project/state.json` | yes |
| Implemented behavior | code in `backend/`, `frontend/` and observed runs | yes |
| Evidence | `.project/evidence/<task>/<run>/` (original outputs) | append only |
| Implementation records | `docs/implement/IMPL-TASK-NNN.md` | yes, one per completed task |
| GitHub issue and PR mapping | `.project/delivery.json` | yes, verified against remote metadata |
| Requirement docs, task specs, task index, data model, `.agent/index.json`, plan progress | generated by `tools/pdd/render.py` | **no** |

## Task workflow

1. Pick a task whose marker is `[]` and whose dependencies are `done`. Set `execution` to `in_progress` in `.project/state.json` with a detail line, then run `python3 tools/pdd/render.py`.
2. Implement only what is in scope. Stop on a stop condition and record it as `blocked` with the reason.
3. Verify every acceptance criterion with the listed method. Keep the original outputs under `.project/evidence/TASK-NNN/run-XX/` and write `report.json` in the plan-driven-development evidence format.
4. Write `docs/implement/IMPL-TASK-NNN.md` from `docs/implement/IMPL-TEMPLATE.md`. Record deviations and known gaps honestly.
5. Set `execution` to `done`, add the evidence path, the implementation record and the criterion results to the state, then render.
6. Run the checks below before committing.

A task that changes code behavior is not `done` on a model's self-assessment alone. Scaffold, documentation and configuration tasks close on structural, build or manual evidence (see `project.yaml` → `verification.manual_completion_policy`).

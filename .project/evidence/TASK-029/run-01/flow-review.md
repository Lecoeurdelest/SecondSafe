# Flow review

AC-PAY-06-1 and AC-PAY-06-2. Inspected `approveWithdrawal`, `rejectWithdrawal` and `requirePendingWithdrawal` in `backend/src/modules/payments/withdrawal.service.js`, `approveWithdrawal` and `rejectWithdrawal` in `backend/src/modules/payments/wallet.controller.js`, and `updateWithdrawalStatus` in `backend/src/modules/moderator/moderator.service.js`. Both the admin routes under `/api/wallets/admin/withdrawals` and the moderator route `/api/moderator/withdrawals/:id/status` call the same service; no other code changes a withdrawal. Approval runs in `session.withTransaction`: the transaction is re-read as pending inside the session, the wallet balance is checked and reduced, and the withdrawal is completed with the balance before and after, so the debit and its ledger record commit together (INV-01). Rejection never reads the wallet. A request that is not pending is refused with 400 in both paths. Which role owns approval is decision D-105; the implementation follows its recommendation (admins and moderators) and is not accepted yet.

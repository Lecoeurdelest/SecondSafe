# Flow review

AC-DSP-01-2. Inspected `createDispute` and `openDispute` in `backend/src/modules/reports/report.service.js`. Input validation finishes before a session starts. `openDispute` runs inside `session.withTransaction`: the order is read with the session, the buyer, the order status and the absence of an earlier dispute are checked, the dispute is created with `{ session }`, and the order is saved as `disputed` with the same session. Any throw aborts the transaction, so the dispute and the status change commit together or not at all. `tests/disputes.test.js` asserts the shared session and that a failed dispute write leaves the order unsaved. Once the order is `disputed` it no longer matches the `delivered` filter of the automatic completion job (delivered with TASK-046).

# Flow review

AC-MOD-03-1 and AC-MOD-03-2. Inspected `resolveReport`, `validateModerationDecision`, `warnReportedUser`, `recordWarning`, `removeListingAfterRepeatedWarnings`, `removeReportedListing` and `banReportedUser` in `backend/src/modules/reports/report.service.js`, and `getReportWarningPenalty`. A processed report is refused before anything changes. The decision is validated first; the sanction for the decision runs before the report is saved, so a refused sanction (an admin target of `ban_user`) leaves the report pending. `recordWarning` increments `violationCount` for every warning and applies a restriction only when the new count is a multiple of the first configured threshold, with the duration taken from `sanctionDurationsMs` (24 hours, 1 week, 1 year). `warnReportedUser` and `banReportedUser` skip or refuse admins (INV-04). The repeated-warning rule counts earlier resolved `warn_user` reports for the listing and adds the one being resolved, because that report is not saved yet; at three the listing is set to `rejected`. The moderator endpoint and `PUT /api/reports/:id/resolve` both call `reportService.resolveReport`.

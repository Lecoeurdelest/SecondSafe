# Flow review

AC-SYS-01-1, AC-SYS-02-1, AC-SYS-03-1, AC-NFR-REL-03-1. Inspected `cancelUnpaidOrders`, `cancelUnpaidOrder`, `completeDeliveredOrders`, `refundUnshippedOrders` and `forEachSafely` in `backend/src/services/order-jobs.service.js`, and `runJob`, `schedule` and `JOBS` in `backend/src/services/cron.service.js`. The timeout job selects orders awaiting payment past their deadline and cancels each with a filtered update (`status: awaiting_payment`), so a payment that lands at the same moment wins and the job skips the order; the listing returns to `active` only if it is still reserved. Completion selects delivered orders older than `autoCompletionWindowMs`, drops any that have a dispute, and calls `escrowService.releaseFunds(..., true)`, which pays the seller, completes the order and marks the listing sold in one transaction and refuses a hold that is no longer held. The refund job selects paid orders older than `shippingWindowMs` and calls `escrowService.refundFunds`. `forEachSafely` catches and logs each failure and continues. `runJob` skips a job that is still running and catches every error; this guard lives in process memory, so two server instances would each run the jobs. Payment deadlines now come from `PAYMENT_WINDOW_MS` instead of an inline three minutes.

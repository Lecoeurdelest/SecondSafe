# Flow review

AC-MOD-04-2. Inspected `updateOrderStatusByModerator`, `completeOrderByModerator`, `completeReleasedOrder` and `forceCancelOrder` in `backend/src/modules/moderator/moderator.service.js`, and `forceCancelOrder` in `backend/src/modules/orders/order.service.js`. The requested status is checked against `MODERATOR_ORDER_TRANSITIONS` before anything changes. `cancelled` requires a note of at least ten characters and delegates to the order service: a paid order is refunded by `escrowService.refundFunds`, which refunds, cancels the order and reopens the listing in its own transaction; an unpaid order is cancelled in a transaction of its own. `completed` requires an escrow hold in status `held`, calls `escrowService.releaseFunds`, then completes the order and marks the listing sold. No wallet or transaction document is written outside the escrow service (INV-01). The order service refuses to cancel completed orders. Known limit: a manual release and the order update that follows are two steps, not one transaction.
